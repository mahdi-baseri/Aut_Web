# تمرین عملی HTTP - Reverse Proxy و JWT

در این پروژه یک پراکسی با Node.js نوشته شده که درخواست‌های HTTP را قبل از رسیدن به سرویس اصلی بررسی می‌کند. برای ورود به سرویس باید یک JWT معتبر در هدر درخواست باشد. سرویس اصلی `go-httpbin` است و همراه پراکسی با Docker اجرا می‌شود.

## ۱. محدود کردن دسترسی سرویس به شبکه داخلی

برای اینکه یک سرویس مستقیماً از بیرون در دسترس نباشد، می‌توان آن را فقط روی IP داخلی اجرا کرد، دسترسی به آن را با فایروال محدود کرد یا در Docker پورت آن را روی سیستم میزبان منتشر نکرد.

در `compose.yaml` سرویس `legacy` فقط عضو شبکه `private_side` است و برای آن `ports` تعریف نشده است. بنابراین درخواست از سیستم میزبان باید ابتدا به `proxy` برسد. پراکسی به هر دو شبکه وصل است و می‌تواند درخواست‌های مجاز را به `legacy:8081` بفرستد.

گزینه `expose` صرفاً پورت مورد استفاده سرویس را مشخص می‌کند و مثل `ports` آن را روی میزبان منتشر نمی‌کند.

## ۲. TLS Termination

TLS برای رمزگذاری ارتباط بین کلاینت و سرور استفاده می‌شود. وقتی TLS Termination روی Reverse Proxy انجام شود، اتصال HTTPS در پراکسی خاتمه پیدا می‌کند و پراکسی درخواست را به سرویس پشت خودش ارسال می‌کند.

این کار برای سرویس قدیمی مفید است، چون لازم نیست خود آن سرویس مدیریت گواهی HTTPS را انجام بدهد. البته اگر ارتباط پراکسی با سرویس داخلی از نوع HTTP باشد، اطلاعات در آن بخش رمزگذاری نمی‌شوند؛ پس شبکه داخلی هم باید امن باشد.

JWT و TLS کاربرد متفاوتی دارند: JWT اعتبار درخواست را بررسی می‌کند و TLS داده‌های مسیر ارتباط را رمزگذاری می‌کند.

در این تمرین، طبق تنظیمات پروژه، ورودی پراکسی روی پورت ۸۰ و با HTTP است و TLS Termination پیاده‌سازی نشده است. برای استفاده روی اینترنت عمومی باید HTTPS اضافه شود تا توکن در مسیر به شکل متن ساده منتقل نشود.

## ۳. پیاده‌سازی پراکسی با JWT

مراحل پردازش درخواست به این صورت است:

1. درخواست به پراکسی روی پورت ۸۰ می‌رسد.
2. مقدار `Authorization` خوانده می‌شود و توکن از `Bearer` جدا می‌شود.
3. امضای JWT با الگوریتم `HS256` و همچنین زمان انقضای آن بررسی می‌شود.
4. توکن نامعتبر یا غایب پاسخ `401 Unauthorized` دریافت می‌کند.
5. درخواست معتبر با همان متد و مسیر به `legacy:8081` ارسال می‌شود.
6. پاسخ سرویس داخلی به کلاینت برگردانده می‌شود.

برای ساخت و بررسی JWT از ماژول داخلی `crypto` در Node.js استفاده شده است. فایل `make-token.js` یک توکن با اعتبار یک ساعت برای آزمایش تولید می‌کند.
